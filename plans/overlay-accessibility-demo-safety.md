## 动机

夜班侦探已经有 Demo 抽屉、睡眠硬件中心、好友线索二维码和 Injective 链上归档四类高层弹层，但它们各自实现了不同程度的 Escape、滚动锁定和焦点恢复：部分弹层可以 Tab 到背景导航，部分关闭后焦点丢失，Demo 抽屉甚至没有 `dialog` 语义。与此同时，“观看 90 秒演示”在只是打开控制台时就调用 `begin()`，章节跳转、完整案件板、真结局快照和重置都会改写当前案件存档，却没有统一、可审阅的影响说明或确认步骤。

## 范围

- 建立一套仓库内复用的对话框生命周期：初始焦点、Tab 焦点圈、Escape 关闭、背景 inert、页面滚动锁定和关闭后焦点恢复。
- 接入 Demo 抽屉、睡眠硬件中心、好友线索分享与 Injective 归档，不改变各弹层业务逻辑。
- 给 Demo 抽屉补齐 `dialog` 名称、影响说明和操作级确认；仅打开 Demo 控制台不再启动或改写案件。
- 区分章节快照、完整案件板、真结局快照和重置的影响文案；明确只影响当前案件，其他案件存档隔离。
- 避免 Shift + D 在输入框、其他模态层或内容编辑状态中误触。
- 增加键盘、背景 inert、滚动锁定、焦点恢复、取消确认与真实执行的浏览器回归。
- 更新稳定交互、架构、演示脚本和质量基线。

## 非目标

- 不建立完全独立、退出后自动回滚的 Demo 沙盒存档。
- 不改变 `jumpToChapter`、`unlockBoard`、`reset` 的游戏状态结果。
- 不重做各弹层视觉内容、NFT 流程、硬件授权或二维码分享。
- 不把 toast、非模态机会告示或晨报折叠区改成对话框。
- 不合入待审 PR #24 或 #26。

## 验收标准

- 四类弹层打开后焦点进入弹层，Tab／Shift+Tab 不离开，背景不可聚焦或交互，Body 不滚动；Escape 或关闭按钮退出后恢复到触发器。
- Demo 抽屉具有可访问名称；仅打开再关闭不会把新案件标为开始，也不会更改章节或已有进度。
- 所有会改写当前案件的 Demo 快捷操作都先展示具体影响并等待确认；取消不改变存档，确认仍得到原有演示结果。
- “重置当前案件存档”明确说明不影响其他案件，并必须二次确认。
- Shift + D 不会在输入框、可编辑区域或另一个模态弹层之上打开 Demo。
- 三档视口下确认区、关闭按钮和主要动作不小于 44 px，无横向溢出或被底部导航遮挡。

## 决定记录

- 2026-07-24：把弹层与 Demo 语义作为第三笔独立 UI/UX PR。它解决的是跨功能的交互可信度，不应和收藏信息架构或故事内容绑定。
- 2026-07-24：不在本 PR 引入独立 Demo 存档域；改为“打开控制台零写入，执行快照前明确确认”。这能修复误触和隐性改写，同时保持黑客松演示的既有状态工具。
- 2026-07-24：统一生命周期沿对话框祖先链隔离背景兄弟节点，并精确恢复原有 `inert` 与 `aria-hidden` 状态；四类弹层共享初始焦点、焦点圈、Escape、滚动锁定和触发器恢复。
- 2026-07-24：桌面浏览器验收中，Demo 抽屉在 1280 × 720 下为 440 px 宽、无横向溢出，背景 5 个节点进入 inert；章节确认区完整位于视口内，打开后初始焦点落在关闭按钮，确认时落在取消按钮。

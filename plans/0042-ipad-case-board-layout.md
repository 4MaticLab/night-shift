## 动机

iPad 竖屏宽度落在手机与桌面断点之间，案件板继续使用桌面双栏和固定画布高度。密码台加入后，上方内容进一步增长，案板工作区被撑出异常长的空白区域，联合推理栏被推到视口外，玩家只能看到底部导航而无法理解下一步。

## 范围

- 在 iPad 竖屏宽度复现并测量案件板、画布、推理栏和底部导航。
- 为平板竖屏建立文档流布局，让密码台、画布、推理操作台、证物档案和核心推论依次可读。
- 保留桌面拖动整理能力；平板竖屏采用更适合触控和滚动的案板行为。
- 增加 iPad 竖屏自动化回归并同步响应式质量文档。

## 非目标

- 不重做密码谜题、证物内容或联合推理规则。
- 不改变桌面宽屏案板和 390×844 手机既有信息顺序。
- 不修改存档、证物坐标结构或结局条件。
- 不直接 push `main`；完成后停在主题分支，发布通过 PR。

## 验收标准

- 768–1024 px 竖屏下案件板不产生横向溢出或异常长空白，推理栏可通过自然纵向滚动抵达。
- 画布、联合推理、证物档案和核心推论维持清晰顺序，底部导航不遮挡关键交互。
- 平板触控不会被 React Flow 画布困住；桌面端仍可拖动图钉并保存位置。
- 既有桌面和 390×844 关键路径不回归。

## 决定记录

- 2026-07-24：用户提供 iPad 竖屏截图并要求直接检查本机浏览器。
- 2026-07-24：范围属于仓库内、可回滚的既有响应式体验修复；提案由 `proposed` 批准为 `approved` 后进入施工。
- 2026-07-24：根因是 601–900 px 单列规则继承桌面 `align-items: start`，同时案板与推理栏继续保留 760 px 固定高度，使案板收缩为 32 px、React Flow 收缩为 0 px，并制造两段伪空白。
- 2026-07-24：手机及 1024 px 以下竖屏平板统一采用触控案板模式；画布禁用拖动、平移和缩放并允许 `pan-y`，桌面和横屏继续保留手动排布。
- 2026-07-24：以 820×1180 Playwright 几何断言锁定案板宽度、推理栏衔接、触控动作和横向溢出。

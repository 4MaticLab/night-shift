# 决策记录

## ADR-001：黑客松版本采用单页面状态机

- 日期：2026-07-23
- 状态：已采用
- 背景：首个版本需要在 90 秒演示内稳定完成首页、交接、夜间、晨报、案件板和结局。
- 决定：使用一个客户端产品外壳承载不同游戏视图，而不是为每个阶段建立独立路由。
- 代价：`app/page.tsx` 体积较大，长期维护需要组件与功能域拆分。
- 后续：[[plans/0003-mvp-quality-hardening]]。

## ADR-002：故事事实完全确定性

- 日期：2026-07-23
- 状态：已采用
- 背景：悬疑体验不能因模型输出漂移而改变真相。
- 决定：章节、线索、人物关系、报告事实和结局条件均由版本化内容定义；生成能力不得决定因果。
- 代价：新增案件需要作者化内容与校验，而不是无限生成。
- 相关：[[docs/story-bible]]、[[docs/architecture]]。

## ADR-003：默认 local-first

- 日期：2026-07-23
- 状态：已采用
- 背景：现场演示不能依赖账户、密钥或不稳定后端。
- 决定：浏览器本地保存进度；无后端和环境变量也能完成核心循环。
- 代价：当前版本不支持跨设备同步。
- 相关：[[docs/product-overview]]。

## ADR-004：文档与计划分层

- 日期：2026-07-23
- 状态：已由 ADR-015 调整
- 背景：长期自动迭代需要区分稳定知识与待执行工作。
- 决定：`docs/` 保存当前真相，`plans/` 保存未来改变；[[AGENTS]] 定义工作循环，[[PLANS]] 维护唯一计划索引，内部导航使用双链。
- 代价：每次非微小变更都需要同步维护索引和状态。
- 相关：[[docs/documentation-guide]]、[[plans/README]]。

## ADR-005：等待留下夜印，准备物只改变回响

- 日期：2026-07-23
- 状态：已采用
- 背景：需要借鉴专注计时的可见生长和放置旅行的行前准备，又不能把睡眠变成惩罚或资源兑换。
- 决定：每次完成一夜都会留下持久化夜印；玩家每夜选择一件随身物，它只改变环境观察、人物反应与路线趣闻，不改变主线线索和结局真相。
- 代价：每件新随身物都要为每章编写固定回响，内容成本增加。
- 相关：[[docs/north-star]]、[[plans/0004-literary-city-and-waiting-loop]]。

## ADR-006：真实夜班由时间戳恢复，不依赖后台倒计时

- 日期：2026-07-23
- 状态：已采用
- 背景：浏览器后台计时会被节流，玩家也应该能在锁屏、关闭页面后继续一夜调查。
- 决定：交接时持久化开始时间，返回与结算时以墙上时间重新计算经过分钟；Demo 仍保留 12 秒压缩流程。
- 代价：本地设备时钟变化会影响实际时长，且当前版本不支持跨设备同步。
- 相关：[[docs/architecture]]、[[plans/0003-mvp-quality-hardening]]。

## ADR-007：受信任的编译期案件包注册表

- 日期：2026-07-23
- 状态：已采用
- 背景：单案件内容虽为数据驱动，但引擎、存档、分享和页面仍绑定首案常量，无法在同一客户端安全切换剧本。
- 决定：用经过运行时校验的 `CampaignManifest` 组合案件事实、路线、推理、结局、逐夜叙事与视觉配置，并通过编译期注册表选择；通用引擎只接收 manifest，不按案件 ID 分支。
- 代价：案件仍需随可信前端构建发布；新作者必须补齐完整内容契约与自动化，暂不支持远程下载 storylet 或任意脚本。
- 相关：[[docs/campaign-authoring]]、[[docs/architecture]]、[[plans/0025-multi-campaign-runtime]]。

## ADR-008：沙盒案件与五夜案件共享注册表、隔离运行时

- 日期：2026-07-23
- 状态：已由 ADR-016 撤销
- 背景：《黑水溪》的双入口、乱序地点、NPC 状态、污染和开放收场无法由连续五夜模型忠实表达，把它压成固定章节会失去主要玩法。
- 决定：`CampaignManifest.format` 在同一编译期注册表中区分 `linear-night` 与 `sandbox-expedition`；沙盒使用通用条件／效果结算器、通用界面和独立 `night-shift-sandbox-v1` 存档。前两案不迁移。
- 代价：manifest 暂时保留一层线性兼容字段；好友线索与共享城市系统也暂不自动适用于沙盒。长期可在更多沙盒案件验证后再收紧为真正的 TypeScript 判别联合。
- 相关：[[docs/blackwater-creek-adaptation-bible]]、[[docs/campaign-authoring]]、[[plans/0026-blackwater-creek-sandbox-adaptation]]。

## ADR-009：沙盒世界状态复用核心延迟探索会话

- 日期：2026-07-23
- 状态：已由 ADR-016 撤销
- 背景：《黑水溪》的开放地点与 NPC 状态适合独立沙盒内容层，但行动点击后即时结算绕开了 Night Shift 最有辨识度的交接、等待与归来循环。
- 决定：保留沙盒的地点、条件／效果与独立存档，把行动运输层改为 `day → night → morning → day`，并直接复用核心 `SleepSession`、12 秒 Demo、真实时间恢复和城市时辰。睡眠质量只改变叙事丰富度，不进入沙盒行动效果计算。
- 代价：线性与沙盒仍有两套页面编排和存档字段；共享的是时间会话与产品伦理，而不是强行统一章节模型。未来抽取更多共享 UI 前，先用第二个沙盒案件验证抽象。
- 相关：[[docs/architecture]]、[[docs/blackwater-creek-adaptation-bible]]、[[plans/0027-sandbox-delayed-expedition-loop]]。

## ADR-010：睡眠硬件作为可撤销的独立感官层

- 日期：2026-07-23
- 状态：已采用
- 背景：智能戒指、手表、床垫和枕头能让真实休息与异步调查产生联动，但黑客松阶段无法可靠依赖厂商 SDK、OAuth、原生权限或云端令牌服务。
- 决定：建立厂商无关的睡眠信号契约、独立本地存档与四类完整虚拟设备；案件运行时只在共享 `SleepSession` 边界通知硬件域。真实厂商入口只做明确标注的桥接预演。硬件信号只产生运行时投影与最近摘要，不进入剧情结算、健康诊断或原始时间序列持久化。
- 代价：浏览器虚拟设备只能证明产品体验，不能证明真实传感精度或平台权限可行性；未来每个厂商接入都仍需原生／服务端实现和独立隐私评审。
- 相关：[[docs/sleep-hardware-bridge]]、[[docs/privacy-and-guardrails]]、[[plans/0028-sleep-hardware-bridge]]。

## ADR-011：本地化是案件内容的只读展示投影

- 日期：2026-07-23
- 状态：已采用
- 背景：首案需要面向英文玩家，但翻译不应复制剧情数据、改变稳定 ID、触发存档迁移或让未完成翻译的案件出现混合语言。
- 决定：中文 manifest 继续作为唯一规范内容；语言目录只替换字符串值，语言偏好使用独立 localStorage 键。每个案件显式声明支持语言，未支持时完整回退中文。英文内容随构建提交，不在运行时调用远程翻译或生成服务。
- 代价：新增语言需要穷举内容覆盖、人工文学复核、ID／规则同构测试和独立浏览器路径；共享城市内容也需要随首个支持它的英文案件一并维护。
- 相关：[[docs/architecture]]、[[docs/campaign-authoring]]、[[plans/0030-last-tram-english-i18n]]。

## ADR-012：运行时 AI 只写经过授权的晨间短笺

- 日期：2026-07-23
- 状态：已采用
- 背景：Hack the Rest 版本需要让玩家把现实中的未完成事项暂时交给夜晚，也需要证明运行时 AI 价值；开放生成案件事实会破坏悬疑确定性，默认上传私人纸条则违背 local-first。
- 决定：放下纸条默认只在本机保存；部署须以独立访问码、HMAC 签名会话 Cookie 和 Redis 跨实例配额保护模型额度，玩家验证后再逐夜主动选择是否发送。访问尝试、单会话调用、部署每日预算和不可变请求 ID 幂等均服务端执行；配额不可用时不调用模型。服务端只把该纸条和最小叙事上下文发送到 OpenAI-compatible 端点；模型只返回固定语气／意象枚举，实际短笺由服务端模板组合。任何缺少配置、权限失效、失败或无效输出都降级为带真实原因的确定性本地回信。模型输出不进入夜间结算、睡眠评价、奖励或结局。
- 代价：现场启用 AI 多一步访问码验证，模型表达空间也被压缩为受限风格选择；换来的收益是模型端点不成为匿名公共代理、自由文本无法越过内容边界，同时保留无密钥可玩、低数据暴露和案件事实稳定。
- 相关：[[docs/privacy-and-guardrails]]、[[docs/architecture]]、[[plans/0032-ai-rest-intention-ritual]]。

## ADR-013：密文关卡是可选档案层，不是结局门槛

- 日期：2026-07-23
- 状态：已采用
- 背景：案件板已有证物配对推理，但黑客松现场还需要一个更直接、可以在十几秒内亲手完成的解密动作。若把谜题设为主线门槛，卡关会破坏“每次休息都推进故事”的承诺。
- 决定：案件密文台从既有证物逐段开放，文本答案只与作者白名单做确定性匹配；三关完成后再用点击排序把答案接成案件规定的电报字段。错误、撤回、重置、提示和跳过均无惩罚。解密结果按案件保存在独立 ID 列表中，只展开补充旁注和案件专属完成回执，不进入夜间结算、核心推论或真结局资格。首案用票孔／字母码／时刻表和 `WHEN → WHO → WHERE`，第二案用调频／计费／摩尔斯和 `SENDER → CHANNEL → MESSAGE` 验证同一运行时可承载不同题材。
- 代价：密文不会提供稀有奖励或改变结局，每个新案件仍需创作自己的谜面、提示和最终字段；换来的收益是现场可演示、可反复尝试且不阻断异步主循环。
- 相关：[[docs/architecture]]、[[docs/product-overview]]、[[plans/0034-night-cipher-desk]]、[[plans/0035-rain-radio-signal-lab]]、[[plans/0036-cipher-relay-sequencing]]。

## ADR-014：刻度盘是答案输入器，不是另一套结算

- 日期：2026-07-23
- 状态：已采用
- 背景：文本输入适合字母码和算式，却无法表现“调准站钟／锁定频率”的题材手感。若刻度盘直接拥有自己的结算与存档，会复制答案规则并制造浮点与迁移风险。
- 决定：关卡可选声明范围、步长、目标和显示模式；组件只管理临时刻度、接近反馈和输入交互，锁定时把格式化读数交回既有 `solveCipher` 白名单校验。只有成功关卡 ID 持久化，错误刻度、尝试次数和信号强度都不保存。
- 代价：刻度盘只能表达一维数值谜题，复杂机械仍需新输入器；换来的收益是时刻与频率共享同一机制，同时保持确定性答案和 v16 存档不变。
- 相关：[[docs/architecture]]、[[plans/0037-interactive-cipher-dials]]。

## ADR-015：复杂任务计划只在主题分支施工期存在

- 日期：2026-07-24
- 状态：已采用
- 背景：永久递增编号、全局唯一施工计划和完成后保留文件适合早期单代理线性迭代，但多人并行时会制造编号竞争、索引冲突和无界目录增长。计划的主要价值在开工审查和阶段推进，完成后的长期事实属于 `docs/`。
- 决定：复杂任务在实现前以 `plans/<branch-slug>.md` 建立临时计划，并把计划与活动索引作为分支第一笔提交；不同主题分支可各自拥有 `in_progress`。验收后先提交完整验证证据，再于 PR 前删除计划和活动索引项。计划型 PR 禁止 squash，默认用 merge commit 保留创建、推进、完成和退役提交；计划正文从 Git 历史取回。
- 代价：主线工作树不再直接展示已完成任务的计划全文，查询者需要知道计划路径、PR 或提交；分支若被 squash 合并会丢失已删除计划，因此合并策略成为流程约束。0001–0043 legacy 计划暂时保留以维持旧反链，后续清理需独立迁移。
- 相关：[[AGENTS]]、[[PLANS]]、[[plans/README]]、[[docs/documentation-guide]]。

## ADR-016：案件书架只承载统一的 Night Shift 生命周期

- 日期：2026-07-24
- 状态：已采用
- 背景：《黑水溪》虽然复用了延迟 `SleepSession`，但玩家改为调度另一支调查队，页面、导航、世界状态和存档也完全独立。它在案件书架中表现为另一款游戏，削弱“你睡了，林渡干活”的系列身份，并让共享注册表承担两套产品生命周期。
- 决定：撤销 ADR-008 与 ADR-009，从现行产品移除 CASE 003、`sandbox-expedition`、独立沙盒引擎／store／UI 和专属自动化。案件包仍可改变题材、人物、地区、谜面和固定事实，但必须共享白天推理、睡前交接、林渡夜间调查与清晨归报的生命周期。旧沙盒 localStorage 不主动删除；旧 `case-003` 活动选择通过注册表白名单安全回落到默认 CASE 001。
- 代价：不再把开放地点沙盒视为同一客户端的可插拔案件格式，已完成的原型只从 Git 历史恢复；未来若重做该类玩法，应按独立产品评估，或先完整改写为 Night Shift 案件而不是复活运行时分叉。
- 相关：[[docs/product-overview]]、[[docs/campaign-authoring]]、[[docs/blackwater-creek-adaptation-bible]]。

## ADR-017：Injective 藏品采用服务端 EIP-712 领取凭证

- 日期：2026-07-24
- 状态：已采用
- 背景：黑客松版本需要把玩家带回的收藏品接入 Injective，同时保持“后端签完、前端 mint”的现场演示手感；直接把服务端私钥或密码下发浏览器会让任何人获得永久签名能力。
- 决定：使用 Injective EVM Testnet ERC-721。服务端只为编译期案件注册表中的收藏品签发绑定接收钱包、案件、收藏、元数据哈希和 15 分钟期限的 EIP-712 voucher；前端钱包调用合约 `redeem`，合约承担签名校验和最终去重。浏览器仅保存公开回执，整个域与游戏存档、睡眠数据和结局资格隔离。
- 代价：需要部署 Solidity 合约、准备测试网 INJ 并保管服务端签名密钥；进程内 API 限流不等同生产级跨实例防滥用。换来的收益是密钥不下发、钱包仍亲自 mint、未配置时完整 local-first 降级。
- 相关：[[docs/injective-keepsake-mint]]、[[docs/architecture]]、[[docs/privacy-and-guardrails]]。

## ADR-018：第三案保留退役 ID 缺口并使用专属视觉包

- 日期：2026-07-24
- 状态：已采用
- 背景：案件书架需要第三个完整 Night Shift 五夜案例来证明内容扩展能力；已退役 Blackwater Creek 曾使用 `case-003`，旧浏览器可能仍保存该 ID。第二案又复用了首案部分画面，不能充分证明剧本与视觉都能作为独立内容包接入。
- 决定：《黎明前出炉的第十三个面包》在书架显示 CASE 003，技术 ID 使用 `case-004`，让旧 `case-003` 继续按非法案件安全回落。案件使用 34 张专属静态 WebP，覆盖四幕、夜印、明信片、植物、收藏、人物和城区；通用运行时仍只读取 manifest，不按新 ID 增加业务分支。

## ADR-019：第四案把“多个原本”适配为五夜异步调查

- 日期：2026-07-24
- 状态：accepted
- 背景：《千早诺亚的第十三次旅行》原始策划包含三夜实时同行、即时选择版本与长期搭档关系，直接搬入会破坏 Night Shift 的“你睡了，我干活”生命周期。
- 决定：只保留十三次抵达、未成线生活与观察者裁决的固定因果，把调查重排为五夜 `CampaignManifest`。通用 `defineCampaign` 明确拒绝非五夜案件；返照镜台只增加数据驱动计数刻度，不参与主线或结局。第四案技术 ID 为 `case-005`、书架号为 `004`，并使用 34 张专属静态 WebP。
- 代价：展示编号与技术 ID 不再连续一致，维护者必须从 `presentation.archiveNumber` 理解书架编号；专属视觉显著增加仓库体积和内容制作成本。换来的收益是旧存档不被误解释，并形成可复用的完整案件交付基线。
- 相关：[[docs/thirteenth-loaf-story-bible]]、[[docs/art-prompts/thirteenth-loaf-visual-archive]]、[[docs/campaign-authoring]]。

## ADR-019：最新晨报由历史快照重放，结束当日独立推进

- 日期：2026-07-24
- 状态：已采用
- 背景：晨报主按钮同时承担“去案件板整理线索”和 `continueDay()`，导致玩家完成归档后回到「今晨」只能看到空页；报纸阅读状态与章节推进被错误绑定。
- 决定：当前 `morning` 保持到玩家明确结束当日；去案件板只切换视图。`day／ready` 阶段的「今晨」从最新 `completedReports` 章节及既有方向、随身物、成长、社团、纪念物和会话快照重放同一份报纸，不新增报告副本或存档字段。
- 代价：只提供最新一份晨报重放，不保存滚动位置，也不建立历史报告选择器；换来的收益是线索归档、晨报重读和下一夜准备各自拥有明确动作，刷新后仍保持一致。
- 相关：[[docs/product-overview]]、[[docs/architecture]]、Issue #19。

## ADR-020：案件板改为可检索档案与确定性推论合成

- 日期：2026-07-24
- 状态：已采用
- 背景：React Flow 案件板把阅档、拖拽、A／B 选择、错误配对和结果回看压在同一画布，并在窄屏产生手势与遮挡负担。底层内容实际已经知道正确证物组合，要求玩家穷举连线只是在隐藏作者答案。
- 决定：用 `syntheses` 配方图替换二元关系；输入可引用原始线索或已合成推论，运行时校验未知引用、重复输出与循环。案件板改为可搜索／筛选的统一档案库和只显示已到齐配方的推理台，玩家明确点击后才归档推论。移除画布坐标与 React Flow 依赖。持久化版本升至 v18，低版本存档直接清为首案新档，不承担尚无真实用户时的兼容复杂度。
- 视觉约束：这是纯玩法重构。继续复用现有 Cozy Storybook Noir 的纸张、黄铜、墨色、蝴蝶封印、字体、颜色变量与证物图，不生成、不替换、不重绘任何美术资产。
- 代价：玩家不再拥有自由摆放证物的桌面感，旧开发存档会被清空；换来的收益是线索可直接阅读、行动项可发现、手机自然滚动、推论可链式扩展，并消除无意义的配对试错。
- 相关：[[docs/product-overview]]、[[docs/architecture]]、[[docs/campaign-authoring]]、[[docs/viewport-checklist]]。

## ADR-021：Home Assistant 通过 loopback 桥成为独立空间外设域

- 日期：2026-07-24
- 状态：已采用
- 背景：比赛版本需要接入通用房间硬件，但普通网页无法可靠发现 HomeKit、Matter 或局域网设备，也不应保管 Home Assistant 长期令牌。现有睡眠硬件域又承载健康数据最小化语义，不能把灯光和插座伪装成睡眠来源。
- 决定：用只监听 `127.0.0.1` 的 Node 本地桥连接 Home Assistant WebSocket API；浏览器经六位码显式配对，只读取归一化白名单实体，并发送 `night.started`、`wake.echo`、`morning.arrived` 三种幂等语义 cue。桥只翻译场景、灯、开关和风扇的固定动作，传感器只读，危险域与任意 service 拒绝。空间外设使用独立 store，只持久化启用和实体 ID 绑定，任何错误都不阻塞游戏状态机。
- 代价：比赛机必须同时运行本地前端与桥；公网部署不能自动控制观众电脑的 localhost，桥重启也会丢失配对和临时恢复快照。换来的收益是 Home Assistant token 不落前端、局域网能力边界明确，并可复用 Home Assistant 已有的 HomeKit、Matter、Zigbee 与厂商集成。
- 相关：[[docs/home-assistant-ambient-bridge]]、[[docs/sleep-hardware-bridge]]、[[docs/privacy-and-guardrails]]、[[docs/architecture]]。

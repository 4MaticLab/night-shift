# 隐私与健康数据护栏

## 数据边界

- 睡眠硬件摘要只保存在当前浏览器／移动 WebView 的 `night-shift-sleep-hardware-v1`。
- 存档最多保留最近 8 条会话摘要，不保存逐分钟心率、呼吸、动作或睡眠分期曲线。
- 安装后的 iOS／Android App 只向 HealthKit／Health Connect 请求睡眠读取权限；不请求写权限、心率、血氧、呼吸或活动权限。
- 系统健康原始样本只在内存中用于合并时间窗；持久化仅包含时长、派生质量、深睡分钟、醒转次数、置信度与来源名称。
- 当前版本不上传健康数据，不建立账号，不请求厂商 OAuth，不保存 API 令牌。
- 权限按信号类别展示；“入睡与醒来时刻”是建立设备夜班的最低字段，其他字段可取消。
- 撤销授权会停止活动设备采集并清除授权状态；案件夜班继续运行。

## Home Assistant 空间外设

- 空间外设与睡眠／健康域分离。Home Assistant 的灯、场景、开关、风扇和环境传感器状态不进入 `night-shift-save-v1`、睡眠摘要、剧情结算或结局资格。
- `HA_TOKEN` 只由监听 `127.0.0.1` 的 Connector 读取并默认保留在进程内存，不进入前端包、浏览器存档、日志或桥 API 响应。浏览器以显式六位码换取 12 小时随机 bearer；bearer 只存在于当前标签页 `sessionStorage`，服务端只保存摘要。
- 浏览器只在 `night-shift-ambient-hardware-v1` 保存启用状态和用户选择的实体 ID 绑定；完整实体清单、原始 `state_changed` 事件和设备状态仅存在于运行内存。
- 可控制域严格限制为 `scene`、`light`、`switch` 与 `fan`，传感器只读；门锁、车库门、安防、摄像头、警报、脚本、自动化和任意 service 调用拒绝。
- 玩家必须先配对、选择实体、试运行并主动开启自动响应。每次动作前验证实体仍在白名单且可用；“恢复原状态”只尽力恢复本次桥进程抓取的灯、开关和风扇前态。
- 外设 cue 只表达夜班阶段，不读取或推断健康状态。桥未运行、令牌失效、Home Assistant 断线或设备命令失败时，游戏继续推进且不降低内容。
- Vercel 网页只请求固定 loopback 地址，由 Chrome Local Network Access 权限门控；mDNS 与任意局域网发现只在用户启动的 Connector 内发生。origin 采用精确白名单，设置 API 只接受自身 loopback origin。

## 放下纸条与 AI 回信

- 放下纸条是可选输入，默认只写入当前案件的浏览器本地存档，不触发网络请求。
- AI 风格选择默认关闭；部署必须配置独立访问码，用户验证后只取得 24 小时 HttpOnly、SameSite Strict Cookie，访问码本身不进入游戏存档。只有仍有访问授权且玩家当夜主动开启时才请求模型。
- 模型请求只包含本夜纸条、案件／章节标题、调查方向、地点、随身物与侦探名，不包含睡眠时长、心率、呼吸、动作、历史纸条、线索存档或设备标识。
- `OPENAI_API_KEY`、`REST_REFLECTION_ACCESS_CODE` 与 Upstash Redis 凭据仅从服务端环境读取，不进入客户端包或浏览器存档；可用 `OPENAI_BASE_URL` 与 `OPENAI_MODEL` 指向兼容端点。
- AI 只有在持久化配额服务可用时启用：原子 Redis Lua 按可信平台地址每小时限制 8 次访问尝试、部署每日限制 200 次；单授权会话每日最多生成 10 次，部署默认每日预算 200 次，并以纸条 `requestId` 做 15 分钟跨标签页／实例幂等。局部与全局计数、TTL 和幂等声明在单次原子操作中完成；配额服务失效时关闭 AI，不降级为无保护调用。
- 模型不是自由写作者，只能返回 `gentle／quiet／steady` 与 `lamp／paper／rain` 两个固定枚举；实际短笺由服务端安全模板组合，因此模型不能向页面注入诊断、建议或新案件事实。
- 未配置、权限失效、超时、上游失败或输出不合约时使用本地确定性回信；晨报区分未发往模型与已尝试但失败，核心循环始终无密钥可用。

## 产品表达

虚拟硬件读数是交互模拟，不是医疗设备数据。晨报必须标注虚拟样机、置信度与“非医疗结论”。安装后的 Apple Health／Health Connect 只有在系统授权流程完成后才能显示已连接；晨报只有实际查到摘要时才能显示系统来源。Oura、Fitbit 和厂商私有入口在 SDK／OAuth 闭环完成前只能称为“桥接预演”，不能使用“已连接”“同步成功”或其他会让玩家误认为真实数据已被读取的措辞。

睡眠摘要不得用于诊断、治疗建议、危险告警、雇佣或保险判断。睡眠质量和任何设备指标都不得减少线索、污染人物状态、锁定结局、制造失败或形成排行榜。

## 背景音乐偏好

- 全局音乐只在浏览器 `night-shift-bgm-enabled-v1` 保存是否开启，不记录播放进度、收听时长、设备、页面历史或身份。
- 音频从站点自身的 `/audio/c-minor-nocturne.mp3` 提供，不连接流媒体、广告、分析或第三方音频服务。
- 浏览器拒绝自动播放时只等待玩家下一次可信交互，不请求额外权限、不以静音播放规避策略。
- 页面隐藏时暂停以减少后台耗电；音乐失败或文件缺失不影响游戏。完整行为见 [[docs/background-music]]。

## 密文笔记本

- 案件密文草稿只保存在浏览器 `night-shift-cipher-notes-v1`，按案件 ID 隔离，最多 1200 字纯文本。
- 草稿不进入 `night-shift-save-v1`、好友线索链接、二维码、AI 回信、钱包元数据、睡眠摘要或日志。
- 客户端不会分析、评分、自动补全或从草稿提取答案；复制与导出只由玩家主动触发。
- 清除需要二次确认；清站点数据会删除全部本地草稿，不提供云同步或恢复承诺。

## Injective 公开回执

- 钱包连接与 mint 完全自愿；不连接时不减少内容，钱包地址不写入案件或睡眠硬件存档。
- 钱包地址、token ID 和交易哈希一旦写入公链就是公开且难以撤销的信息。界面必须明确标注测试网、无购买、无通关证明和无游戏优势。
- 浏览器只在 `night-shift-injective-mints-v1` 保存公开回执，不上传本地案件进度、睡眠摘要、纸条、好友线索来源或其他历史。
- `INJECTIVE_MINT_SIGNER_PRIVATE_KEY` 只存在于 Next 服务端；API 返回限时 EIP-712 voucher，不返回私钥、部署密钥或可复用开放签名能力。
- 元数据由受信任案件 manifest 生成，不能夹带玩家输入、健康数据或自由文本。部署域名进入永久元数据前应使用固定 origin。
- 完整流程、环境变量与合约边界见 [[docs/injective-keepsake-mint]]。

## 未来真实接入门槛

新增睡眠来源至少需要：厂商最新文档复核、最小权限评审、令牌不落前端、撤销与删除路径、离线／无数据状态、数据保留周期、平台隐私声明，以及真实设备与模拟数据的视觉隔离。当前 Apple Health／Health Connect 满足本地只读闭环；厂商私有 SDK／OAuth 尚未接入。Home Assistant 只覆盖空间环境设备，不能被宣传为睡眠传感器。任何新增上传、账号或云同步都必须建立新的 `manual` 计划并由用户批准。

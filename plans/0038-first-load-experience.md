## 动机

首页包含高完成度画面、三套案件内容与多条游戏功能链路。慢速网络或冷缓存下，用户会先看到未就绪页面或短暂无响应，却没有明确的加载反馈；同时入口模块同步引用多个非首屏游戏界面，增加了首次加载压力。

## 范围

- 增加与现有品牌美学一致、可在服务端首帧出现的加载幕。
- 以真实的应用 hydration、字体与当前首页主视觉状态决定退出，不使用无限固定假进度。
- 为资源失败或异常慢网提供超时兜底，不把用户困在加载幕。
- 将案件板、夜班、硬件与黑水溪等非首屏组件改为按需加载。
- 覆盖桌面、390×844 移动端、中文、英文与慢网回归。

## 非目标

- 不重做首页内容与案件选择结构。
- 不压缩或重新生成现有美术资产。
- 不引入服务端账户、遥测或第三方加载服务。

## 任务

- [x] 明确首载就绪信号、超时与无障碍规则。
- [x] 实现服务端首帧与客户端接管一致的品牌加载幕。
- [x] 拆分非首屏游戏模块并保留现有交互。
- [x] 增加自动化覆盖与稳定文档。
- [x] 完成浏览器、测试、lint、构建与文档验收。

## 验收标准

- 冷加载时立即出现加载幕，不显示半成品首页或可误点控件。
- 当前案件主视觉完成或失败、应用已 hydration、字体准备完成后，加载幕平滑退出。
- 最长等待受控；资源失败时仍可进入产品。
- reduced-motion 用户不会看到持续位移动画。
- 首页与既有三案件、硬件、分享及中英文测试保持通过。

# 睡眠硬件用户连接指南

本指南面向网页玩家，说明怎样在 Night Shift 中连接当前可用的虚拟睡眠硬件、完成一夜测试并查看晨报回执。整个案件不依赖设备：不连接、拒绝权限、撤销授权或数据不完整，都不会减少线索或阻断结局。

> 当前网页版本可以真实完成“虚拟硬件”链路；Apple Health、Health Connect、Oura Cloud 与 Fitbit Web API 仍是接口预演，不会读取手表或健康平台数据。看到“桥接预演”时，不应把它理解为已经连接成功。

## 开始前准备

- 使用最新版 Chrome、Edge 或 Safari 打开网页。
- 允许浏览器使用本地存储；隐私／无痕模式可能在关闭页面后清空设备授权和回执。
- 进入任一案件的“今晚”页面。
- 若只想快速检查流程，优先选择“演示旅程”；若想验证刷新恢复和实际计时，选择“今夜真实交接”。

## 连接虚拟手表

1. 在页面右上角点击“睡眠硬件”或在睡前交接页点击“打开硬件台”。
2. 确认进入“虚拟硬件”页签。
3. 选择“十七号夜表”。它最接近智能手表，提供睡眠窗口、睡眠分期、心率和动作摘要。
4. 检查拟保存字段：
   - “入睡与醒来时刻”用于建立夜班边界，是设备会话的最低字段；
   - 睡眠分期、心率、动作可以按页面允许的范围逐项关闭；
   - 页面不会保存原始逐分钟时间序列。
5. 点击授权按钮，等到页面显示“连接完成，可以回到游戏了”。
6. 关闭硬件中心。顶栏或睡前交接卡应显示“设备已接”及设备名称。

## 完成一次 2 分钟网页验收

### 演示旅程

1. 选择任一调查方向，保留“演示旅程”。
2. 点击“今晚交给你了”。
3. 夜班页应显示设备正在记录，并出现与授权字段对应的信号摘要。
4. 点击“跳到清晨”。
5. 晨报中找到睡眠硬件回执，确认包含：
   - 虚拟设备名称；
   - 本夜时长和派生摘要；
   - “仅本机摘要”和“非医疗结论”；
   - 没有原始曲线或诊断措辞。

### 今夜真实交接

1. 在交接方式中选择“今夜真实交接”。
2. 点击开始后刷新页面，夜班、开始时间和设备采集状态应继续存在。
3. 可点击一次“我只是醒了一下”，确认夜班不会结束且同一夜不能重复记录。
4. 点击“我醒了，拆开报告”，检查晨报中的实际计时和本机摘要。

## 查看、撤销与删除

- 再次打开“睡眠硬件”，可查看当前授权和最近摘要。
- 点击“撤销授权”后，设备不再参与下一夜采集，但案件继续。
- 当前网页最多保留最近 8 条摘要，存储键为 `night-shift-sleep-hardware-v1`。
- 如需彻底清除，可在浏览器站点设置中删除该站点的本地数据；这也可能清除案件存档，请先确认。

## 小米手表用户说明

Xiaomi Watch S4 等小米穿戴设备需要先与 Mi Fitness 配对。小米官方说明中，手表睡眠记录在同步后可在 Mi Fitness 的“健康 → 睡眠”查看；Google Play 上的 Mi Fitness 应用说明也列出了 Health Connect 数据同步能力。但不同地区、系统、应用版本和数据类型可能不同。

当前 Night Shift 网页不能直接读取 Mi Fitness 或 Android Health Connect。因此现在可以做两件事：

1. 在 Mi Fitness 中确认小米手表确实记录了睡眠；
2. 在 Night Shift 中使用“十七号夜表”完成产品体验测试。

不要在当前版本中把“真实桥接 → Health Connect”展示为小米手表已经接入。开发者真实联调方案见 [[docs/xiaomi-watch-hardware-test]]。

## 常见问题

### 已选设备，但页面仍显示未连接

点选设备只会生成授权草稿；还需要在字段确认区点击最终授权按钮。若正处于夜班采集中，必须先生成晨报，才能更换设备或权限。

### 刷新后设备不见了

检查是否使用无痕模式、浏览器是否阻止本地存储，或站点数据是否被清理。重新授权不会改变案件结果。

### 真实桥接为什么没有授权按钮

该区域用于展示未来厂商映射，当前没有 OAuth、原生 SDK 或令牌服务。请选择页面推荐的同类虚拟设备继续测试。

### 数据看起来不准确怎么办

虚拟硬件数据是确定性模拟，只用于验证交互，不是医疗读数。真实手表数据也受佩戴松紧、固件、同步时机和算法影响，不能用于诊断或治疗。

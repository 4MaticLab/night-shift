# 案件板候选提示与信笺揭示

- 状态：`completed`
- 优先级：P1
- 创建：2026-07-24
- 更新：2026-07-24
- 负责人：Codex
- 分支：`codex/case-board-letter-reveal`
- 依赖：PR #18 的设计审查与关闭
- 推进模式：`manual`

## 动机

PR #18 探索了未结关系提示、兼容线索高亮和信笺式档案／推论揭示，但其实现会在第二件证物被点击时自动确认关系，并用固定底栏替换现有推理台。当前产品已经确立 A／B 选择后显式核对的交互与共享无障碍弹窗规范，因此需要在最新主线上重新实现值得保留的部分。

## 范围

- 从确定性案件关系派生未结关系线索与当前兼容候选，不新增或改变剧情规则。
- 在现有案件板增加线索索引、未结关系提示和选择 A 后的候选高亮。
- 使用共享无障碍弹窗能力实现信笺式证物档案和核对成功后的推论揭示。
- 保留现有 A／B 槽、显式“核对证物”按钮、右侧推理栏与移动端文档流。
- 为桌面、iPad 竖屏和手机补充响应式及端到端验证。
- 同步架构、质量基线与视口检查文档。

## 非目标

- 不自动确认第二件被点击的证物。
- 不引入固定底部核心推论 Dock。
- 不改变 `CampaignManifest.relations`、`connectClues`、结局资格或存档结构。
- 不搬运 PR #18 的 legacy plans 或整段 CSS。
- 不改变好友线索、密文台或其他案件生命周期。

## 任务

- [x] 为案件板增加线索索引和线索卡视觉状态。
- [x] 实现可访问的证物档案信笺，保持分享入口。
- [x] 在显式核对成功后展示可访问的推论信笺。
- [x] 验证错误配对、选择槽、画布滚动和三档视口行为。
- [x] 更新稳定文档并完成完整工程验证。

## 验收标准

- 玩家仍需明确选择 A、选择 B、点击“核对证物”才会确认关系。
- 尚未确认且双方已解锁的关系会进入索引；选择 A 后只高亮与其匹配的候选。
- 阅档与推论揭示均支持 Escape、焦点锁定、背景隔离、滚动锁定和焦点恢复。
- 桌面、iPad 竖屏和 390 px 手机不产生页面横向溢出，画布不截断页面滚动。
- 错误配对不写入存档，成功配对仍生成持久连线并影响原有结局条件。
- `npm test`、`npm run lint`、`npm run build`、`npm run docs:check` 和相关 Playwright 场景通过。

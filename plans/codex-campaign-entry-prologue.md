# 案件导入序章与首夜生命周期

- 状态：`in_progress`
- 优先级：P0
- 创建：2026-07-24
- 更新：2026-07-24
- 负责人：Codex
- 分支：`codex/campaign-entry-prologue`
- 依赖：无
- 推进模式：`manual`

## 动机

当前新存档虽然会经过三页通用操作说明，但没有讲清案件怎样来到事务所、委托人带来了什么异常、林渡为什么要在今晚出门。玩家因此把进入游戏感知成“选完剧本就准备睡觉”，首夜交接缺少叙事动机，也让各案件的独特悬念直到夜间报告后才出现。

用户已明确要求暂停新剧本施工，优先修正这一共享玩法生命周期。

## 范围

- 为 `CampaignManifest` 增加确定性的案件序章内容契约。
- 把新案件首次进入流程改为三拍式案件导入：接案异象、委托／证物、林渡首夜交接。
- 四个现有案件分别提供与固定真相一致的序章，不增加分支结局或隐藏状态。
- 保留通用“你睡着以后，林渡才工作”的规则说明，但让它服务于案件情境。
- 已开始案件继续从原存档进入，不重复强制播放序章。
- 同步更新案件创作、架构、产品生命周期与质量基线文档。

## 非目标

- 不继续新增第五案或扩写现有案件夜数。
- 不改变五夜结算、线索、联合推理、睡眠硬件或结局条件。
- 序章选择不产生数值、路线、奖励或存档分叉。
- 本计划不猜测用户尚未说明的第二个玩法问题；收到后先判断是否需要独立计划。
- 不为序章生成一套平行美术资产；优先复用各案件已经过审的主视觉与交接资产。

## 任务

- [ ] 定义并校验案件序章数据结构，补充内容层测试。
- [ ] 设计响应式案件序章 UI，明确进度、返回、继续与最终接案动作。
- [ ] 接入首页到首夜的状态流，确保新存档播放、继续存档跳过、切换案件隔离。
- [ ] 为四个案件写入三拍式序章；已支持英文的案件同步完整英文投影。
- [ ] 更新稳定文档与端到端验收。
- [ ] 在桌面、平板和手机视口人工走查首案与另一案件的首次进入流程。

## 验收标准

- 新存档点击“开始案件”后，首屏即出现该案件专属异象与案件名，而不是抽象教程或睡眠配置。
- 玩家在进入首夜准备前，已经看见委托／证物、核心疑问和林渡的首夜调查目标。
- 序章三拍均可明确前进和返回，最终动作语义是“接下案件／进入事务所”，不会误导为立即睡觉。
- 四案序章共享同一组件和生命周期契约，但文本与已审美术属于各自案件。
- 返回案件库再继续已开始案件时不强制重播；重置该案件后可重新播放。
- 390×844、820×1180 与桌面视口无横向溢出，主要操作满足触控尺寸。
- 现有五夜流程、存档隔离、内容校验和中英文首屏测试不回退。
